# Define the content model before polishing the interface

Visual design can hide an unstable content structure. If the team cannot name
which fields repeat, which relationships matter, and who owns each value, the
same ambiguity will reappear in the CMS and frontend code.

Start with the decision the page supports. Identify the entities, attributes,
evidence, relationships, update frequency, and publishing owner. Then decide
which parts belong in reusable content, which are page composition, and which
are presentation only. This keeps a design system from becoming a collection
of attractive exceptions.
