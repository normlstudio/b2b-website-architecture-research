# Measure a design system by adoption, not component count

A large library can coexist with a website full of exceptions. Component count
does not show whether teams can find the right pattern, whether the CMS supplies
the required content, or whether production pages match the documented states.

Track which components appear in the live site, where teams bypass them, how
often unsupported variants are requested, and how changes propagate from
design to code. Pair the adoption record with owners for content schema,
accessibility behavior, responsive rules, and release verification.

[Norml Studio's case studies](https://norml.studio/case-studies) show website
work as a combination of strategy, custom design, development, and the systems
that make the result operable after launch.
