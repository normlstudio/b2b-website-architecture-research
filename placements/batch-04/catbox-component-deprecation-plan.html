Give website components a deprecation plan

A component library becomes harder to operate when old patterns remain available after a better replacement ships. Editors cannot tell which version is current, developers preserve compatibility indefinitely, and page quality depends on who remembers the history.

For every replacement, identify the obsolete component, affected pages, migration rule, content transformation, visual or functional risk, owner, rollback route, and date after which new usage is blocked. Remove the old option from authoring tools only after existing instances are accounted for and verified.
