Define the CMS governance boundary

A content system needs a boundary between reusable business data, page composition, presentation, and application logic. Without it, routine edits become development work while visual exceptions accumulate inside the CMS.

Document which entities repeat, which relationships matter, which teams own each field, and which changes require review. Give editors control over content decisions they understand, not over implementation details that can break consistency or accessibility. Keep schema, validation, versioning, preview, and rollback behavior explicit.
