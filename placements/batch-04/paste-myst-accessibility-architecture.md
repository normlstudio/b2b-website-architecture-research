# Accessibility decisions start before component QA

Accessibility problems are expensive to repair when they are treated as a
final visual audit. Heading relationships, reading order, form ownership,
keyboard paths, status messages, media alternatives, and content language all
begin in structure and content modeling.

Add accessibility requirements to the page and component contracts. Identify
the user task, semantic outline, interaction states, error behavior, alternative
content, and person responsible for maintaining each piece. Verify the rendered
experience with automated checks and human keyboard and screen-reader review
where appropriate.
