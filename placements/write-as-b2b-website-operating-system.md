# A B2B website needs an operating system, not another launch file

The visible page is only one part of a B2B website. The harder test is whether the company can explain, change, measure, and maintain the system after launch.

An architecture review should trace four connected layers.

## Buyer decisions

List the decisions the website must help a buyer make. Then check whether navigation, page order, proof, and calls to action support those decisions. A sitemap is useful when it explains relationships, not when it merely inventories URLs.

## Content ownership

Record where each important fact lives and who owns it. Repeated services, industries, people, proof, FAQs, and resources need a content model that prevents drift. Unknown ownership is an architecture finding, not a copywriting problem.

## Technical behavior

Check templates, components, CMS structure, responsive behavior, accessibility, canonical URLs, structured data, analytics, forms, integrations, environments, deployment, and recovery. Mark what is observed, reported, unknown, or not applicable.

## Improvement loop

Every recommendation needs an owner and a verification step. Recheck the original behavior after a change ships. A recommendation is not complete merely because a ticket or design was approved.
