# A B2B interface needs a decision log

An interface change is rarely only visual. Moving a call to action can alter the
content hierarchy, analytics event, component contract, form context, campaign
message, and the way an editor maintains the page later.

## Capture the reason

Record the user problem, evidence, approved decision, affected templates,
implementation owner, and expected public behavior. This makes the reasoning
reviewable after the original meeting and avoids conflicting fixes.

## Trace the dependencies

Before release, map the decision across design tokens, reusable components,
CMS fields, responsive states, accessibility behavior, analytics, and linked
sales material. A shared component should not be changed as though it belongs
to one page.

## Close with evidence

Verify the production URL at representative viewport sizes, test the action,
inspect metadata and structured data, and record the release. If the observed
result differs from the decision, the log should make correction or rollback
straightforward.
