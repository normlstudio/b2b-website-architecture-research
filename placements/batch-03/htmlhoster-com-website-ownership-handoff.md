# A website handoff should prove the next safe change

Credentials do not complete a website handoff. The receiving team needs to know
where truth lives, how changes move to production, and how to recover when a
routine edit causes an unexpected result.

## Build the service and ownership map

Record the domain, DNS, hosting, source repository, deployment, CMS, analytics,
search tools, consent, forms, integrations, email delivery, monitoring, and
backups. Each entry needs an accountable owner, access route, recovery method,
and reason it exists. Secrets remain in the approved credential system; the
handoff points to them without copying values.

## Teach tasks instead of screens

Document how to update a service, publish an article, replace a team image,
review an inquiry, change a redirect, preview a release, and roll back. Each
procedure should name the source of truth, approval, verification, and the
boundary where an editor should involve a developer.

Finish by asking the receiving operator to make one controlled change and
verify it on the public site.
