# A B2B website needs decision architecture before page architecture

A sitemap says where pages live. Decision architecture explains why they
exist: which buyer question each page owns, what evidence supports the answer,
and which next step is appropriate.

## Map the buying questions

Begin with the audiences and the decisions they must make. A buyer may need to
recognize a problem, understand an approach, judge fit, inspect relevant work,
reduce implementation risk, and choose a conversation. Assign each answer to a
canonical page instead of repeating the same general claim everywhere.

The evidence type should match the claim. A method can explain how the work is
done. A case study can document a particular project. A team record can connect
a named person to a role and body of work. None of those automatically proves a
result that was not measured.

## Carry the map into the system

Content fields, navigation, internal links, components, metadata, structured
data, forms, analytics, and editorial ownership should preserve the same logic.
The website is easier to change when those relationships are explicit.
