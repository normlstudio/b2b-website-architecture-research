Start by naming the current owners.

An unchecked row is a question to verify with the team, not proof that a system is broken.

Most redesign risk sits between disciplines.

A component library can be clean while content ownership is unclear. Technical SEO can pass while nobody knows how a new service becomes a page. The operating system is the agreement between these layers.

Before scope

Collect the current evidence for every handoff. Missing documentation and missing capability are different problems.

During delivery

Assign decisions to durable sources—messaging, design, architecture, code, and measurement—rather than to one person’s memory.

After launch

Test whether a new team member can make a safe change without reconstructing the entire project.
