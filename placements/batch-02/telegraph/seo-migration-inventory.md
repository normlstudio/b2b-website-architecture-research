A website migration can preserve page titles and still lose the logic that helped people and search systems understand the business. The safer starting point is an inventory of the promises each public URL currently makes.

## Record what each URL owns

For every indexable page, I would capture the canonical URL, status, title, main topic, important query intent, internal links, backlinks when known, structured data, conversion action, and content owner. The inventory should also flag duplicate pages, obsolete claims, and pages with no clear purpose.

This is more useful than a flat redirect list because it explains why the URL matters. A page with external references, a distinct audience, or a unique service answer may need different treatment than a thin archive page.

## Decide before mapping redirects

Each old URL needs a documented outcome: preserve, merge, replace, archive, or remove. A redirect should point to the closest valid replacement, not automatically to the homepage. Internal links, navigation, XML sitemaps, canonicals, and structured data must follow the same decision.

Changes to names, services, industries, or proof deserve human review. A migration should not carry an old claim merely because it exists in the source CMS.

## Verify the public system

After launch, crawl both URL sets, test redirects, compare indexability and metadata, inspect key templates, and monitor search-console evidence. Keep the inventory as the correction ledger until the new site has been checked over time.
