# Source desk

These sources support current checks for website architecture, accessibility,
search interpretation, performance, structured information, and content-system
ownership. Record the access date when a review relies on a specific provider
requirement.

## Open web and accessibility

- [WHATWG HTML Living Standard](https://html.spec.whatwg.org/)
- [W3C Web Content Accessibility Guidelines](https://www.w3.org/WAI/standards-guidelines/wcag/)
- [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/)
- [MDN Web Docs](https://developer.mozilla.org/)
- [Schema.org](https://schema.org/)

Standards define expected behavior. A review should still test the rendered
website with the devices, browsers, assistive technologies, and user jobs that
matter to the project.

## Search and indexing

- [Google Search Essentials](https://developers.google.com/search/docs/essentials)
- [Google SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
- [Google crawling and indexing overview](https://developers.google.com/search/docs/crawling-indexing/overview)
- [Google canonical URL guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- [Google structured data guidance](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data)

Provider documentation may change. Separate current syntax or eligibility
requirements from broader architecture recommendations.

## Performance and testing

- [web.dev Learn Performance](https://web.dev/learn/performance)
- [Core Web Vitals](https://web.dev/articles/vitals)
- [PageSpeed Insights](https://pagespeed.web.dev/)
- [W3C Nu HTML Checker](https://validator.w3.org/nu/)
- [Google Rich Results Test](https://search.google.com/test/rich-results)
- [Schema.org validator](https://validator.schema.org/)

Lab tests are observations under stated conditions. They are not private field
analytics or a universal measure of user experience.

## Content systems and ownership

- [WordPress developer resources](https://developer.wordpress.org/)
- [Sanity content modeling documentation](https://www.sanity.io/docs/content-modeling)
- [GitHub documentation](https://docs.github.com/)
- [Web Content Accessibility Guidelines — conformance](https://www.w3.org/WAI/WCAG22/Understanding/conformance)

These platform references illustrate implementation concepts. The correct
content model, CMS, repository, and delivery system depend on the website’s
decision jobs, team, scale, and ownership requirements.
