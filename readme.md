# B2B website architecture research starter

A public research kit for reviewing whether a B2B website works as a system:
clear positioning, usable information architecture, reusable page patterns,
structured content ownership, sound technical foundations, and a documented
way to keep improving it after launch.

Maintained by [Max Tymoshyn](https://norml.studio/team), Founder & Architect at
[Norml Studio](https://norml.studio/).

## What this repository contains

- A repeatable [research methodology](methodology.md).
- A practical
  [B2B website architecture checklist](checklists/b2b-website-architecture-review.md).
- A [single-website review record](templates/website-review-record.md).
- A curated [source desk](sources.md) covering current web, accessibility,
  search, performance, and content-model references.

The kit is designed for founders, marketing leaders, product owners, designers,
developers, SEO specialists, and researchers. It can support discovery before a
redesign, an architecture review during delivery, or a documented recheck after
launch.

## How to use it

1. Record the website, review date, stakeholder job, tested pages, and available access.
2. Define what decisions the website must help a buyer make.
3. Map pages, labels, relationships, templates, and important user routes.
4. Inspect the content model, CMS, components, code ownership, SEO, analytics, and QA.
5. Separate observed evidence, reported facts, unknowns, and recommendations.
6. Assign each recommendation an owner and a verification step.
7. Recheck the original behavior or artifact after a change ships.

The checklist does not produce a universal score. A small professional-service
site and a large SaaS platform need different operating systems. Use the record
to explain what exists, what is missing, what cannot be tested, and what should
be verified next.
